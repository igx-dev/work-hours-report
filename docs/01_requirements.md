# 要件定義

最終更新: 2026-11-23

## 目的

日々の作業時間をその日のうちに記録し、プロジェクトの工数が予定に対してどこまで進んでいるかを、管理者がいつでも見られるようにする。

- 入力は1日1分で終わること(スマホのブラウザからも入力でき、前日の内容を複製して直せる)
- 集計を手で作らないこと(月末に表計算で集める作業をなくす)
- 出し忘れを仕組みで減らすこと(未提出の人にだけ通知する)

## 利用者

| ロール | 人 | できること |
| --- | --- | --- |
| member | 作業者 | 自分の日報の入力・修正・一覧 |
| admin | 管理者 | member の操作 + プロジェクトの管理、全員分の閲覧、ダッシュボード、CSV 出力 |

ロールは Cognito のグループで分ける。1人が両方を持つこともある。

## 機能要件

| ID | 機能 | ロール | 提供先 |
| --- | --- | --- | --- |
| F-01 | ログイン(メールアドレス + パスワード) | 全員 | Web |
| F-02 | 日報の登録・修正・削除(日付、プロジェクト、時間、メモ) | member | Web |
| F-03 | 前日の日報を複製して登録 | member | Web |
| F-04 | 自分の日報の一覧(月単位) | member | Web |
| F-05 | プロジェクトの登録・修正・終了(名前、予定工数、期間) | admin | Web |
| F-06 | ダッシュボード: プロジェクト別の月次工数の推移 | admin | Web |
| F-07 | ダッシュボード: 予定工数と実績工数の比較 | admin | Web |
| F-08 | ダッシュボード: プロジェクト内のメンバー別内訳 | admin | Web |
| F-09 | 工数の CSV 出力(月単位) | admin | Web |
| F-10 | 未提出者の名前を Slack のチャンネルに投稿(平日 18:00) | member | Slack |
| F-11 | 週次レポートを Slack に投稿(月曜 9:00) | admin | Slack |

### 入力ルール

- 時間は 0.25 時間(15分)単位、1件 0.25〜24 時間
- 同じ日・同じプロジェクトの日報は1件(登録し直すと上書き)
- 1日の合計が 24 時間を超える登録はエラー
- 終了したプロジェクトには登録できない
- 修正できるのは当月と前月の分まで(締めた月は admin だけが直せる)

## 非機能要件

| 項目 | 要件 |
| --- | --- |
| 構成 | サーバーを持たない。すべてマネージドサービスで、使った分だけの課金にする |
| 性能 | API の応答は 1 秒以内(p95)。利用者は数十人まで、1プロジェクトの日報は数千件までを想定する |
| 可用性 | AWS のマネージドサービスの可用性に従う。独自の冗長化はしない |
| セキュリティ | 通信はすべて HTTPS。API は Cognito のトークンがないと呼べない。member は他人の日報を読めない |
| 環境 | dev / prod を同じ IaC から作る |
| 費用 | 月 500 円を超えたら知らせる(AWS Budgets) |
| 監視 | Lambda のエラーと API の 5xx を CloudWatch アラームで検知し、Slack に通知する |
| データ保持 | 日報は 5 年保持。DynamoDB のポイントインタイムリカバリを有効にする |
| 対応ブラウザ | PC: Chrome / Edge / Safari の最新版。スマホ: iPhone の Safari、Android の Chrome の最新版 |
| 画面 | レスポンシブ。画面幅 360px 以上で崩れない |

## 対象外(今回はやらない)

- 勤怠(出退勤の打刻)や給与計算との連携
- 承認ワークフロー(日報の差し戻しなど)
- SSO(Google / Microsoft アカウントでのログイン)
- スマホ専用のアプリ(Web をレスポンシブにし、スマホのブラウザから使う)
