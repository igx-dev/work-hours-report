# フロントエンド設計

最終更新: 2026-11-23

画面は Web の SPA 1つだけ。PC でもスマホのブラウザでも同じ操作ができるよう、レスポンシブに作る。

## 技術

| 項目 | 選択 |
| --- | --- |
| 言語 | TypeScript(strict) |
| フレームワーク | React 19 + Vite。ルーティングは React Router |
| 状態管理 | Redux Toolkit。サーバーのデータは RTK Query、画面をまたぐ状態(ログイン情報、選択中の月)は slice |
| API の型 | `api/openapi.yaml` から `openapi-typescript` で生成 |
| 認証 | Amplify Auth(Cognito) |
| グラフ | Highcharts(`highcharts-react-official`) |
| テスト | Jest + Testing Library。API は MSW でモックする(`src/mocks/` の見本の API を、テストと見本モードで共用する) |
| Lint / 整形 | ESLint + Prettier |
| 配信 | S3 + CloudFront。どのパスも `index.html` を返す設定にする |

## 画面

| 画面 | パス | 内容 | ロール |
| --- | --- | --- | --- |
| ログイン | `/login` | メールアドレスとパスワード | 全員 |
| 日報入力 | `/?date=YYYY-MM-DD` | 日付を選ぶ(最初は今日。隣に前の日・次の日・「今日」のボタンがある)。左に登録済みの日報と「新規追加」、押したものを右で編集する(プロジェクトは変えられない)。新規追加では、まだ登録していない進行中のプロジェクトだけを選べる。時間は ±ボタン(15分刻み)。削除の前に確認のダイアログを出す | member |
| 自分の日報 | `/reports` | 月の一覧。その月の全部の日を並べ、日報がない日は「未入力」と出す(土日は薄い色)。どの日も、押すと一覧の下にその日の編集が出る(「日報入力」と同じ部品) | member |
| ダッシュボード | `/dashboard` | 全プロジェクトの今月の予実と推移 | admin |
| プロジェクト詳細 | `/projects/:id` | 1プロジェクトの推移、メンバー別内訳 | admin |
| プロジェクト管理 | `/admin/projects` | 「日報入力」と同じ形。左に一覧と「新規追加」、押したものを右で編集する(名前、予定工数、期間、状態。終了にしたものは進行中に戻せる) | admin |
| ユーザー管理 | `/admin/users` | 「日報入力」と同じ形。左に一覧(名前、メールアドレス、役割、状態)と「新規追加」、右で編集。追加すると招待メールが届く。利用を止める前に確認のダイアログを出す。自分の管理者の役割と利用は変えられない | admin |
| CSV 出力 | `/admin/exports` | 月を選んでダウンロード | admin |

admin でログインした時の最初の画面はダッシュボード、member は「日報入力」。

削除や利用の停止など、取り消しにくい操作の前には、確認のダイアログ(`components/ConfirmDialog.tsx`)を出す。ブラウザ標準の確認ではなく、画面の見た目に合わせた部品にする。開いた時は「やめる」に焦点を置き、Esc キーでもやめられる。

## レスポンシブ

| 画面幅 | レイアウト |
| --- | --- |
| 〜767px(スマホ) | 1列。メニューは画面下のタブバー(入力 / 日報 / 集計 …。狭いので短い名前にする)。表は横にスクロール |
| 768px〜 | 左にメニュー、右に本文 |

- 作業者がよく使う「日報入力」と「自分の日報」は、スマホで片手で使えることを優先する(ボタンは高さ 44px 以上、時間は ±0.25 のボタンで入力できる)
- ダッシュボードとプロジェクト管理は PC で使うことを主に考え、スマホでは見られれば十分とする
- 画面幅 360px で崩れないことを確かめる
- スマホのホーム画面に追加できるよう、Web アプリマニフェストとアイコンを置く(オフライン対応はしない)

## ダッシュボードのグラフ(Highcharts)

| グラフ | 種類 | 見せること | データ |
| --- | --- | --- | --- |
| 予定と実績 | 横棒(予定を背景の棒、実績を重ねる) | どのプロジェクトが予定を超えそうか | `/admin/dashboard/summary` |
| 月次の推移 | 折れ線(累計)+ 予定工数の水平線 | このままのペースで予定に収まるか | `/admin/dashboard/projects/{id}` |
| メンバー別内訳 | 積み上げ縦棒(月 × メンバー) | 誰に作業が偏っているか | 同上 |

- 色は1つのテーマ(`Highcharts.setOptions`)にまとめ、グラフごとに指定しない
- 予定を超えたプロジェクトだけ警告色にし、他は落ち着いた色にする
- グラフの下に同じ数字の表を置き、色が見分けにくい人も読めるようにする
- 画面幅が変わったらグラフも描き直す(`reflow`)
- Highcharts は商用利用にライセンスが要る。導入前に契約を確認する

## 状態の持ち方

```
store
├── auth        ログイン中のユーザー、ロール(slice)
├── ui          選択中の月、選択中のプロジェクト(slice)
└── api         RTK Query のキャッシュ(日報、プロジェクト、集計)
```

日報を保存したら RTK Query のタグで、その月の一覧とダッシュボードのキャッシュを無効にして取り直す。

## ディレクトリ

```
web/
├── src/
│   ├── app/            store、ルーティング
│   ├── api/            生成した型と RTK Query の定義
│   ├── features/       画面ごと(today, reports, dashboard, projects, exports)
│   ├── components/     共通の部品(月の切り替え、グラフの枠)
│   ├── lib/            日付の計算、入力チェック、ログインの窓口
│   └── mocks/          見本の API(MSW)と見本データ
└── tests/              テストの準備(画面を描く関数、Highcharts の代わり)
```

## 見本モード

`npm run dev:mock` で、AWS につながずに画面を動かせる。API は MSW がブラウザの中で受け、`src/mocks/` の見本データを返す。ログインも見本(メールアドレスが `admin` で始まれば管理者)。画面の確認と、デモのためのもの。

## ログイン

Cognito のユーザーは管理者が作る(自分で登録はできない)。初めてログインした時は仮のパスワードなので、画面で新しいパスワードを決めてもらう。ログインの処理は `lib/auth.ts` の形(`Auth`)にそろえ、本物(Amplify)と見本を差し替えられるようにしている。テストでは見本を使う。
